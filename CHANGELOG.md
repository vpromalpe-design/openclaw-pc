# Changelog

OpenClaw PC — Windows-приложение и установщик для OpenClaw: агенты, модели, голос и Telegram в одном месте.

## 0.10.0 (2026-09-03) — ядро OpenClaw 2.0 (v2026.8.1)

Апгрейд встроенного ядра на OpenClaw 2.0 (v2026.8.1). Ветка `v0.10.0+openclaw.2026.8.1`, база — стабильная v0.9.33 (откат в любой момент).

- **Ядро 2026.7.1 → 2026.8.1** (npm-бандл, `@openclaw/ai` — прямая npm-зависимость: больше не junction-проблема 0.9.18). Control UI из npm-пакета, esbuild-transpile для Electron (маркер `CONTROL_UI_ELECTRON_LIT_MARKER`).
- **Allowlist моделей** переведён на schema 2.0: `agents.defaults.models` → `agents.defaults.modelPolicy.allow` (пишем в оба пути, читатели делают union, миграция с `meta.migrations.modelPolicyAllowlist`).
- **deepseek**: остаётся на обходном `deepseek-direct` — в npm-бандле 2026.8.1 нет физической реализации `deepseek` (плагин требуется отдельно, вне v0.10.0).
- **RPC-клиент**: не шлёт браузерный `Origin` на gateway 2.0 (2.0 молча срезал operator-скопы при browser-origin); повтор с Origin только при быстром отказе рукопожатия — версионно-агностично.
- **Wizard/конфиг**: ключ `gateway.controlUi.allowInsecureAuth` больше НЕ пишется на ядре 2.0 (schema 2.0 его не знает — boot fail); легаси-конфиги чистятся при чтении. `readBundledOpenClawVersion()` + `isKernelTwoOrNewer()`.
- **Патчи ядра**: `silent-reply-local` адаптирован под 2.0-сборщик системного промпта (push переехал в `buildAgentSystemPrompt`, `runtimeInfo?.model`); feishu-канал в 2.0 бандлится по-новому (register-онce не подтверждён), slack — внешний плагин → легаси-патчи тихо no-op на 2.0 (варн только при реальном коде).
- **Фаза 3 — стенд-прогон на VPS закрыт**: pre-migration конфига под 2.0 (doctor 2.0 на сыром 0.9.x-конфиге разрушителен — нужна наша миграция ДО первого boot: `meta.lastTouchedAt`/`agents.defaults.memorySearch`/`allowInsecureAuth`/`tailscale.resetOnExit` снять, `agents.ownership=explicit`); внешние плагины `@openclaw/deepseek-provider|duckduckgo-plugin|llama-cpp-provider` (install с consent) — для прода; prod-шейп RPC (client.id=`gateway-client`/backend): models.list по агентам, cron/tasks/logs живы.
- **Визуал и механики не меняются**: по решению Дамира переносится ВСЁ кроме тумблера CPU/GPU (local-engine) — реестр задач, мульти-боты, «Просто текст», офлайн-голос, визард — на ядре 2.0.
- Watch на релиз: после апгрейда проверить порт 18789 (на стенде gateway слушал 19001 при конфиге 18999 — аномалия); deepseek/duckduckgo/llama-cpp = внешние плагины для прода.

## 0.9.30 (2026-09-01)
- **🔴 ФИКС КОРНЯ «Созданных файлов» и ссылок в ответе** (разведка по живой задаче `lt-1788300515051-7vo0nr`):
  - **Проблема**: в tasks.json записывалось ПЕРВОЕ assistant-сообщение (рассуждение «I need to handle BOOTSTRAP.md…»), а не финальный ответ («Готово 🔥 Файл `fire.txt` создан…») → парсер не находил файлы → блок «Созданные файлы» пуст и ссылок нет.
  - **Причина**: монитор задач финализировал задачу на первом же assistant-сообщении (gateway шлёт session.message на каждый апдейт транскрипта; первое сообщение — часто reasoning без ответа).
  - **Фикс monitor.ts**: debounce-финализация (4 сек тишины после ПОСЛЕДНЕГО assistant-сообщения; любая активность сессии сбрасывает таймер) + перезапись ответа в рамках той же «волны» (позднее финальное сообщение после долгой tool-паузы перезаписывает answer; user-сообщение = новая волна; waiting не перетирается).
  - **activity.ts**: монитору передаются ВСЕ session.message (user → новая волна, toolResult → сброс таймера, assistant → текст).
- **renderAnswerText v2 (TasksView)**: ссылками становятся и полные пути, и резолвнутые имена (`fire.txt` из бэктиков) — клик открывает файл.

- **«Задачи» → «Вывод» (фидбек по 0.9.28)**:
  1. «Созданные файлы» — вместо дерева директорий (уходило вправо) **плоский вертикальный список имён файлов**, клик = открыть, полный путь в подсказке.
  2. В «Ответе агента» полные адреса под «Файл лежит здесь: …» **заменяются на имена-ссылки** — нажатие открывает файл.
  3. Компактнее: убрана внутренняя прокрутка списка файлов (max-h), блоки плотнее — всё влезает в рамки.
  4. Выпадающие меню (⚙️, ⋯, агентское) — **почти непрозрачные** (фон 0.7 → 0.97/0.98), текст читается лучше.

- **Микрофон в «Задачах» — ТОЧНАЯ копия основного чата**: найдена причина «не работает» — готовность кнопки требовала, чтобы установленная модель whisper совпадала с активной (`modelsInstalled.includes(model)`); у Дамира стоит другая модель, чем дефолтная → кнопка вечно серая. Теперь проверка как в чате (`enabled && whisper.installed`). Кнопка заменена на точную копию control-ui `.pc-mic` (капсула 32px: иконка + «Говорите» / «Стоп» / «Распознаю…», красная пульсация при записи, спиннер при распознавании) + тумблер `.pc-mode` «Офлайн/Онлайн» (зелёный/синий, точка) — та же логика (онлайн недоступен без realtime-провайдера).
- **Мастер настройки — единая нижняя панель**: вместо двух панелей на разных уровнях (язык в сайдбаре + футер справа) — ОДНА общая панель на всю ширину окна с ровной линией сверху; слева «Отмена» + язык, справа навигация.

- **Голосовой ввод в «Задачах»**: кнопка 🎤 **справа** от поля, идентичная чату, + **переключатель «Офлайн/Онлайн»** (как в основном чате; режим сохраняется в конфиг); запись → whisper → текст в поле; индикаторы записи/распознавания/ошибки.
- **«Созданные файлы» — реальные файлы агента**: усилен парсер (пути с пробелами/кириллицей, JSON-цитаты, несколько путей, title); **новое: относительные имена в бэктиках (`файл.txt`) резолвятся в существующие файлы** по workspace агента (openclaw.json), Desktop и домашней папке через новый IPC `tasks:resolveFiles` — теперь блок «Созданные файлы» появляется, даже когда агент пишет только имя файла. (Тест 13/13.)

## v0.9.26 — «Созданные файлы» в выводе задачи (2026-09-01, по запросу Дамира)

Во вкладке **Вывод** карточки задачи появился блок **«Созданные файлы»**: если агент
упомянул в ответе/выводе созданные файлы (markdown-ссылка, путь в ``коде``, `file://`
или абсолютный Windows/POSIX-путь), они собираются в дерево директорий и открываются
кликом (shell.openPath). Парсер `extractFileRefs` + дерево `buildFileTree`/`sortFileTree`.

- Источники: `answer`, `terminalSummary`, `question`, `progressSummary` задачи.
- Markdown-ссылки `[label](path)` → подпись = label; бэктик-спаны и свободные пути → имя файла.
- Пути с пробелами — если обёрнуты в markdown-ссылку/бэктики; `file://` декодируется.
- URL (http/https/www) и `//`-протоколы не считаются файлами.
- Папка с трейлинг-слэшем = узел-директория; клик по файлу открывает его в системе.
- Ошибка открытия показывается под блоком.

## v0.9.24 — Рассинхрон моделей устранён + чистый композер (2026-09-01, по баг-репорту Дамира)

Три пункта из отчёта по текущей сборке:

- **1. DeepSeek больше не становится основным автоматически** — при сохранении провайдера (`saveProviderConfig`) убран авто-назначение primary «первой настроенной модели». Провайдер просто добавляется в allowlist и находится «наряду со всеми»; основная модель меняется только явно (визард или кнопка «Подключить» в «Моделях»).
- **2. Единый источник истины — модель активного агента** (`agents.list[].model ?? дефолт`):
  - панель «Состояние» и статусбар раньше показывали только глобальную primary → теперь показывают модель **активного** агента (совпадает с меню агента);
  - «Подключить» в «Моделях» (`applyModelsPriority`) теперь синхронизирует **allowlist** (`agents.defaults.models`) для primary+fallbacks — раньше gateway отклонял выбранную модель вне allowlist, кнопка «нажата, но не работает», фактически оставалась старая модель;
  - меню модели агента подгружает свежий список моделей при **каждом открытии** (не только при старте/refresh) — подключённые модели появляются сразу;
  - после любого действия в «Моделях» (подключить/сохранить/добавить/fetch) шелл обновляется немедленно через `onChanged → refreshShellData`;
  - при выборе модели в меню агента сайдбар/«Состояние» обновляются оптимистично, без ожидания перечитывания конфига.
- **3. Внизу у поля ввода убраны все кнопки и настройки** (CSS-инъекция в Control UI): скрыты селектор модели (`chat-composer-model-control`), скрепка прикрепления (`agent-chat__attach-menu`), чип настроек (`chat-settings-chip`) и model-bar. Остались только поле ввода и кнопка отправки. Выбор модели — только в меню самого агента.
- **4. Голосовой ввод в чате — один микрофон с тумблером Офлайн/Онлайн** (вместо нативной realtime-кнопки Control UI, падавшей «Realtime voice provider is not configured»):
  - кнопка 🎤 у поля ввода + капсула-тумблер; **Офлайн** = запись с микрофона → whisper.cpp (локально, без интернета и ключей), распознанный текст вставляется в поле ввода; **Онлайн** = нативный realtime-talk (если провайдер и ключ настроены в Голос → Онлайн-распознавание);
  - если выбранный способ не настроен — понятная подсказка и предложение другого способа, никаких сырых ошибок ядра;
  - «Голос» → «Распознавание речи»: селектор способа по умолчанию (Авто / Локально / Облако), сохраняется в конфиг оболочки (`sttPreferredMode`) и применяется микрофоном в чате;
  - реализация: патч Control UI (`scripts/lib/patch-openclaw-ui-voice-input.ts`, Lit-компонент `openclaw-pc-voice-input`), мост `openclaw-pc:stt` (шело-сторона в `App.tsx`), IPC `stt:setPreferredMode`.

Проверено: type-check ✅ lint ✅ build ✅.

## v0.9.23 — Модели = мастер (A+B+C по решению Дамира, 2026-09-01)

Страница **«Модели»** после мастера теперь позволяет **абсолютно всё**, что делает мастер настройки — добавление/изменение провайдеров, моделей и ключей:

- **(A) Единый каталог провайдеров** — `src/shared/provider-catalog.ts`: человеческие имена (DeepSeek, OpenRouter, …), endpoint-дефолты и алиасы для всех провайдеров; используется и в main, и в renderer (без дублирования).
- **(A) Сохранение провайдера синхронизирует allowlist** — любая сохранённая модель автоматически дописывается в `agents.defaults.models` (+ primary для первой) и сразу видна в селекторах и меню агентов. Исправлен баг «модель не видна после сохранения».
- **(A) Человеческие имена в таблице** — `deepseek-direct` показывается как «DeepSeek»; дубль-строка канонического `deepseek` скрывается, когда есть `deepseek-direct`.
- **(C) Пикер моделей = merge** — RPC `models.list` + конфиг (`models.providers` + allowlist), dedupe по `provider/id`: видны ВСЕ модели, включая локальные.
- **(B) «Загрузить модели»** — кнопка в панели провайдера и в форме добавления: GET `/models` с API провайдера (Bearer / `x-api-key`+`anthropic-version`, спец-обработка Ollama `/api/tags` и Google `?key=`), результат — готовый список в селекторе модели.
- **(B) Панель провайдера = полный аналог мастера** — API base URL для любого провайдера (префилл из каталога), совместимость для custom, регион Moonshot, Account/Gateway ID для Cloudflare.
- **(B) Секция «Добавить провайдера»** — провайдер + модель + ключ + endpoint + «Проверить» + «Добавить» (мастер-аналог прямо на странице «Модели»).
- **(B) Меню модели агента** — группы «Облачные» / «Локальные», человеческие имена; выбор `local/<model>` реально запускает локальный движок (`localEngineStart`).
- Расширены пресеты моделей (openrouter, mistral, groq, cerebras, huggingface, venice, together, nvidia); локали ru/en/zh.

## v0.9.24 (дополнение) — TTS больше не читает markdown-разметку

- **Озвучка ответов чистит markdown перед синтезом** (`stripMarkdownForSpeech` в `src/main/voice/voice.ts`): убираются `**жирный**`, `*курсив*`, `` `код` ``, `~~зачёркнуто~~`, заголовки `#`, списки, цитаты `>`, ссылки `[текст](url)` (остаётся текст), картинки, HTML-теги и таблицы. Раньше TTS произносил символы разметки («звёздочка звёздочка», «решётка»).
